# Architecture

`config` parses strict TOML, validates status classes and profile-specific settings, and restricts the endpoint to an HTTP loopback address. The HTTP client disables proxies and redirects; `localhost` is pinned to 127.0.0.1. `profiles` declares each profile's capabilities, signature header, and signing behavior. `crypto` signs exact byte slices and verifies HMACs with the `hmac` crate's constant-time verification. `fixture` owns the stable scenario catalog, typed mutation strategies, and deterministic body/header generation. `runner` executes each request, captures only status codes and bounded response bytes, reads optional local observer counts, and classifies results. `report` emits terminal, versioned JSON, and Markdown views.

The reference receiver is a separate binary. It binds only to 127.0.0.1 and exposes test-only reset and observation routes. Each scenario resets its state before delivery; this prevents results from prior scenarios contaminating counts. A mutex protects the receiver's processed-ID set and counters, so concurrent duplicates are evaluated atomically. The concurrent scenario uses a barrier before starting the HTTP requests.

The observer contract is `POST /__webhookproof/reset` returning 2xx and `GET /__webhookproof/observations` returning bounded JSON with `completed_processing_count`. It is intended only for a controlled local test instance. An arbitrary consumer can implement that contract in its test environment; no production middleware dependency is required. Processing assertions read the observer after the configured `observer.settle_ms` window (default 500 ms). If reset or read is unavailable, HTTP assertions still run and processing assertions are INCONCLUSIVE. When `observer.require = true`, unavailable evidence makes the CLI exit with code 2.

The reference receiver's fixture payload contains an `id` field protected by the body HMAC. This makes its idempotency test measurable. It is not a universal GitHub event identity convention. The `delivery-id-only` mode deliberately uses GitHub's unsigned delivery header instead and exposes the weakness in that test contract.
